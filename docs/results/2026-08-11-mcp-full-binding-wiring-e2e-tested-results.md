## Findings

- **Reconcile tooling gotcha (recorded so the next run avoids it).** An initial code-scan reported the entire `#52` identity infrastructure "missing" — it had read the repo's **stale working-tree files** (a `main` checkout predating the `#52`/`#55` merge, so `internal/toolidentity/` was absent on disk). Re-verifying directly against `origin/main` (`git show`/`git ls-tree`) showed everything present. The feature branch cuts from `origin/main`, so the base was always correct. Lesson: on a reconcile, verify code claims against `origin/<integration_branch>`, not the working tree, which may lag the merge.
- **`internal/mcp/oauth.go`: identity-tier servers could not dial (previously-untestable-path defect this change surfaced).** `GetAccessToken` returned `"unknown auth type"` for `auth.type: identity` / `oauth-exchange`, so a server configured for identity propagation failed at dial. Fixed to return `("", nil)` — the transport dials with no static token and each `tools/call` presents its own per-call delegation token (minted at `MCPTool.Execute`). This was invisible until a binding actually attached an identity-tier MCP server end-to-end — exactly the gap `#59` closes.
- **Acceptance-lane hang #1 — SSE teardown ordering (learning `httptest-defer-close-before-tcleanup-deadlock`).** The stub/rentals SSE servers loop on `r.Context().Done()`, so `httptest.Server.Close()` blocks until fuse's SSE read-pump disconnects. Fix: teardown ordering so the MCP **manager/client closes before the server** (`t.Cleanup` LIFO, or `LoopTeardown` before the server's cleanup) — mirroring `internal/mcp/egress_test.go`'s `capturingSSEServer`. This was the cause of an initial 600s `cmd/fuse` package timeout.
- **Acceptance-lane hang #2 — scripted-gateway JSON double-escaping.** The scripted `LLM_GATEWAY_URL` double double-escaped tool-call arguments (call sites passed pre-escaped `{\"listing_id\":\"L1\"}` and the gateway unescaped `\"`→`"` on top of the adapter's own JSON escaping), so the emitted tool call carried malformed args (and, in an earlier revision, a `:`-split tool name of just `mcp`). The tool never dispatched and the loop never closed a turn. Fix: pass **plain** JSON args at the call sites so the single adapter-escape / gateway-unescape round-trips correctly.
- **Review SHOULD-FIX S1 — per-loop MCP manager leak on `StartLoop` failure.** If `StartLoop` failed at `BuildAgent` *after* `NewToolRegistry` attached the per-loop `mcp.Manager`, the manager (and its read-pump/notify goroutines) leaked and the tracking `sync.Map` entry was never cleared. Fixed: the runtime now invokes `Deps.LoopTeardown(toolReg)` on that early-return path, symmetric with the store `Close`. Test: `TestStartLoop_TeardownOnBuildAgentError`.
- **Review SHOULD-FIX S2 — one-shot MCP manager leak on `StartLoop` error.** The one-shot manager was closed only by the completion goroutine, so a `StartLoop` error return leaked it. Fixed: `buildOneShotRuntimeDeps` returns an idempotent (`sync.Once`) close func; `main.go` closes the manager on the error return.
- **Review NIT N1 — wrong-audience now proven through the binding.** Checklist point 5 (wrong-audience rejected) was proven at the seam (`rentals_test.go`) but not through the loop-server binding. Added `TestAcceptance_WrongAudienceThroughLoopServer` (the MCP server config declares an audience the rentals server does not accept, so an otherwise-authorized principal is rejected on audience alone) and corrected a stale doc comment.
- **No new ADR.** The change consumes ADR-0036 (delegated tool authz egress seam), ADR-0034 (edge-enforced tenancy), and ADR-0030 (policy-free runtime seam) and drives them through the bindings. The new `runtime.Deps.LoopContext` / `LoopTeardown` seams are a mechanical, ADR-0030-consistent extension (the runtime imports no auth/mcp type; identity travels as a `context.Context` a composition-root closure decorates, resources release via a `*tools.Registry`), not a new architectural decision.
