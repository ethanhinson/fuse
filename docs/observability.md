# Observability operations

`deploy/observability` is a **development-only** stack: Prometheus, Grafana, an OpenTelemetry Collector, and Tempo. It intentionally omits Loki. Start it with `docker compose -f deploy/observability/docker-compose.yml up`; start `fuse loop-serve-net` separately with metrics on `0.0.0.0:9090`. The collector accepts OTLP on 4317/4318 and routes traces to Tempo. This is not production: production operators own TLS, authentication, network policy, storage, retention, backups, and access review for Prometheus, Tempo, and the log collector.

Metric labels are opaque `tenant_id`, model, and tool identifiers only. Do not put display names, loop/node IDs, trace/span IDs, prompts, payloads, URLs, paths, raw errors, or user-visible names in labels. Keep opaque-ID/display-name mappings in an access-controlled system outside Prometheus. Trace and structured-log metadata are tenant-sensitive operational data; limit access accordingly.

For exact capacity planning, let `T`, `M`, and `U` be the configured tenant/model/tool cardinality budgets, each including its one reserved `__overflow__` value; `R` replicas; `O=7` operations; `Q=4` outcomes; `E=13` event kinds; and `H` histogram buckets. Each configured budget must be at least one, and at most `budget - 1` values may be pinned or admitted from its catalog. Per replica: loop = `T*O*Q + T*O*Q*(H+2) + T*O`; model = `T*M*Q + 2*T*M*Q*(H+2)`; tool = `T*U*Q + T*U*Q*(H+2)`; spawn = `T*Q + T*Q*(H+2)`; projection = `E*Q + Q*(H+2)`; cardinality diagnostics = `9`. Multiply their sum by `R`. `fuse_metrics_label_budget` reports that total configured limit, while `fuse_metrics_label_admitted_values` excludes the reserved overflow value. Export/drop/reopen/override families are bounded by configured repository-owned signal/reason/scope vocabularies and must be budgeted before production rollout. `__overflow__` means incomplete attribution; tenant alerts exclude it and `FuseOverflowAttributionIncomplete` reports it separately. Dashboard `rate()`/`increase()` queries are restart-safe. Logging reload and reopen mutate process-global state and require a trusted `loop_server.auth` principal with `observability_operator: true`; ordinary tenant principals retain only tenant-scoped override control.

Collect stdout through the platform collector. For file logs, use rename-create-reopen rotation: rename the old file, create the replacement with correct ownership/mode, then call the authenticated reopen endpoint (or send SIGHUP). `copytruncate` is unsupported because concurrent writes can be lost or duplicated. An incident journey is Grafana → Tempo trace → approved structured-log collector → authenticated tenant-authorized replay; trace IDs and dashboard URLs never authorize replay.

Run `go run ./deploy/observability/validate.go`; when installed, also run `docker compose -f deploy/observability/docker-compose.yml config`.
