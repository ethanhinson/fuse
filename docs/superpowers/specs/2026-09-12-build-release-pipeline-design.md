# build/release pipeline — design

Change #82 · related #76 (server deployment), #64 (egress forwarder artifact) · ADR-0044, ADR-0051

## The gap, stated precisely

fuse has a build (`make build`), a version stamp (`internal/version.Version`, ldflags-injected,
defaulting to `0.1.0-dev`), and a CI workflow that proves the code (`.github/workflows/integration.yml`:
unit-race, observability-acceptance, egress-datapath, browser-acceptance, mcp-integration). It has
**no release**: no git tag has ever been cut, no binary has ever been published, no container image
exists, and the only documented install path is `make install` from a checkout — which requires a Go
toolchain, and which silently leaves `egress.mode: enforce` deny-all because the linux forwarder
artifact (`cmd/fuse-egress-forward`, change #64) is not placed beside the installed binary.

A user who wants to *try* fuse today must clone, build, and know about the forwarder. This change
makes adoption a single command on macOS and Linux, and a single `docker pull` for the server shape.

## Decisions (settled 2026-09-12 with the human)

| Decision | Choice | Rejected |
|---|---|---|
| Release tool | **GoReleaser** (`.goreleaser.yaml`, pinned major via `goreleaser/goreleaser-action`) | hand-written matrix workflow — more YAML, re-implements archives/checksums/images |
| Trigger | **manual semver tag push** (`v*`); first release `v0.1.0` | release-please — bot PRs on every cycle; premature for a single-maintainer repo |
| Install paths | **GitHub Release archives + SHA256SUMS**, **curl install script**, **multi-arch GHCR image** | Homebrew tap — needs a second repo + PAT; revisit once releases are routine |
| Provenance | **checksums + `actions/attest-build-provenance`** on archives and the image | cosign keyless + SBOM — stronger, more moving parts; a follow-on |

## Artifacts a release produces

For tag `vX.Y.Z`, one GitHub Release carrying:

1. **`fuse_X.Y.Z_<os>_<arch>.tar.gz`** for `darwin/{amd64,arm64}` and `linux/{amd64,arm64}`
   (windows is out of scope — the bash sandbox is container-only and untested there). Each archive
   contains, at its root:
   - `fuse` — the CLI, built `CGO_ENABLED=0 -trimpath -ldflags "-s -w -X …/internal/version.Version={{.Version}}"`.
     Verified 2026-09-12: the module is CGO-free and cross-compiles static for linux/arm64.
   - `fuse-egress-forward-linux-amd64` **and** `fuse-egress-forward-linux-arm64` — **both** forwarders
     in **every** archive, including darwin. Rationale: fuse looks for `<exeDir>/fuse-egress-forward-linux-<hostArch>`
     (`cmd/fuse/sandbox.go`, second lookup path), the sandbox image arch is a deployment fact, and the
     two static binaries are a few MB. Shipping both means an unpacked archive is correct wherever it lands.
   - `LICENSE`, `README.md`.
2. **`fuse_X.Y.Z_checksums.txt`** — SHA256 over every archive.
3. **`ghcr.io/ethanhinson/fuse:X.Y.Z`**, `:X.Y`, `:latest` — a multi-arch (`linux/amd64`, `linux/arm64`)
   manifest. Image contents: `fuse` + both forwarders on a distroless static base
   (`gcr.io/distroless/static-debian12:nonroot`), `ENTRYPOINT ["/fuse"]`, no default CMD (the server
   shape is `loop-serve-net`; the CLI shape is whatever the user passes). The image ships **no**
   container runtime: a bash tool inside it needs the #75 remote substrate or a mounted socket, exactly
   the ADR-0044 tradeoff #76 must make explicit. This change only builds the image; #76 composes it.
4. **Build provenance attestations** (`actions/attest-build-provenance`) over the archives, the
   checksums file, and the image digest, verifiable with `gh attestation verify`.
5. **Release notes** auto-generated by GoReleaser from commits since the previous tag, grouped by
   conventional-commit prefix (`feat`, `fix`, others), with the install snippet as the header.

## The GoReleaser configuration (`.goreleaser.yaml`)

- `before.hooks`: `go mod tidy` check (fail on diff) and `make egress-forwarder` is **not** used —
  GoReleaser builds the forwarder itself so its version stamp matches.
- `builds`:
  - `fuse`: `main: ./cmd/fuse`, `goos: [darwin, linux]`, `goarch: [amd64, arm64]`, `env: [CGO_ENABLED=0]`,
    `flags: [-trimpath]`, `ldflags: -s -w -X github.com/ethanhinson/fuse/internal/version.Version={{.Version}}`.
  - `fuse-egress-forward`: `main: ./cmd/fuse-egress-forward`, `goos: [linux]`, `goarch: [amd64, arm64]`,
    same env/flags/ldflags, `binary: fuse-egress-forward-linux-{{ .Arch }}`, and `no_unique_dist_dir`
    so the two outputs land at stable paths the archives can reference.
- `archives`: one archive per `fuse` build (`builds: [fuse]`), `name_template: fuse_{{ .Version }}_{{ .Os }}_{{ .Arch }}`,
  `files:` adds both forwarder outputs from `dist/` by explicit path, plus `LICENSE` and `README.md`.
  `strip_binary_directory: true` so `fuse` sits at archive root.
- `checksum`: `name_template: fuse_{{ .Version }}_checksums.txt`, sha256.
- `dockers` / `docker_manifests`: two per-arch images built with `use: buildx`, `dockerfile: Dockerfile`,
  `extra_files` = both forwarders; one manifest per tag (`X.Y.Z`, `X.Y`, `latest`). OCI labels for
  source, revision, version, licenses.
- `release`: `github: {owner: ethanhinson, name: fuse}`, `draft: false`, `prerelease: auto`
  (a `-rc.N` tag publishes as a pre-release, `latest` image tag is skipped for pre-releases via
  `skip_push: '{{ .Prerelease }}'` on the `latest` manifest is **not** expressible; instead the
  `latest` manifest is gated with `{{ if not .Prerelease }}` in its `name_template` — see open question 1).
- `changelog`: `use: github`, groups by `^feat`, `^fix`, catch-all; excludes `^docs`, `^chore`, `^test`, `^docket`.

The Makefile keeps `build`/`install`/`egress-forwarder` unchanged for the checkout workflow; nothing
in the release path depends on `make`, and nothing in `make` depends on GoReleaser.

## `Dockerfile`

A two-line-ish distroless image, **not** a multi-stage Go build: GoReleaser has already produced the
binaries, so the Dockerfile only copies `fuse` and the two forwarders into
`gcr.io/distroless/static-debian12:nonroot` and sets the entrypoint. The image is therefore
reproducible from the same build the archives came from. A `make image` convenience target is
**not** added (it would need a second, divergent build path); local image builds go through
`goreleaser release --snapshot --clean`.

## `scripts/install.sh`

Hosted from `main` (`curl -fsSL https://raw.githubusercontent.com/ethanhinson/fuse/main/scripts/install.sh | sh`).
POSIX `sh`, no bashisms. Behaviour:

1. Detect `uname -s` → `darwin|linux`, `uname -m` → `amd64|arm64` (map `x86_64`, `aarch64`); refuse anything else with a clear message.
2. Resolve the version: `FUSE_VERSION` env if set, else the GitHub `releases/latest` redirect (no API token needed).
3. Download the archive **and** the checksums file to a temp dir; verify with `sha256sum` or `shasum -a 256`; abort on mismatch.
4. Unpack; install `fuse` and both forwarders into `FUSE_INSTALL_DIR` (default `$HOME/.local/bin`; `/usr/local/bin` only if the user sets it — never `sudo` implicitly).
5. Print the installed path, run `fuse version` to prove it, and warn if the install dir is not on `PATH`.

It never touches `~/.fuse/config.yml`.

## `fuse version`

A new top-level subcommand in `cmd/fuse/main.go` printing `fuse <version>` (the stamped
`internal/version.Version`) plus `go` runtime version, OS/arch. Today the version appears only in the
banner; the install script and bug reports need a one-line, script-safe form. `fuse --version` is
accepted as an alias.

## The release workflow (`.github/workflows/release.yml`)

```
on: push: tags: ['v*']
permissions: contents: write, packages: write, id-token: write, attestations: write
jobs:
  test:      go test -race ./...                       # the gate — a tag never releases red code
  release:   needs: test
             actions/checkout (fetch-depth: 0, tags)
             actions/setup-go (go-version-file: go.mod)
             docker/setup-qemu-action + docker/setup-buildx-action
             docker/login-action → ghcr.io with GITHUB_TOKEN
             goreleaser/goreleaser-action  (version: ~> v2, args: release --clean)
             actions/attest-build-provenance  (subject-path: dist/*.tar.gz, dist/*_checksums.txt)
             actions/attest-build-provenance  (subject-name: ghcr.io/ethanhinson/fuse, subject-digest from goreleaser's dist/artifacts.json)
```

`timeout-minutes: 30` (the existing workflows cap at 20; buildx + QEMU for arm64 needs headroom).
Every action is pinned to a major tag consistent with `integration.yml`'s style (`@v4`, `@v5`).

### Keeping the config honest on every PR

A new job in `integration.yml`, `release-dry-run`: `goreleaser check` then
`goreleaser release --snapshot --clean --skip=publish,docker` (docker is skipped so PR CI stays
Docker-registry-free; the `egress-datapath` job already proves Docker itself). It then asserts the
snapshot archives exist and that `tar tzf` of the darwin/arm64 archive lists `fuse`,
`fuse-egress-forward-linux-amd64`, and `fuse-egress-forward-linux-arm64` — the archive-layout
invariant fuse's forwarder lookup depends on. This is the test for this change: a `.goreleaser.yaml`
edit that drops a forwarder fails CI, not the next release.

## README

Replace the `## Building` section with `## Installing` (curl one-liner, manual archive download +
verification with `gh attestation verify`, `docker run ghcr.io/ethanhinson/fuse:latest`, and
`go install` as the from-source path with the forwarder caveat) and keep `## Building` below it for
contributors. Add `docs/releasing.md`: how to cut a release (`git tag -a vX.Y.Z -m … && git push origin vX.Y.Z`),
what to check in the Actions run, how to verify artifacts, how to yank (delete the release + tag,
re-tag as a patch).

## Testing

- **Unit**: `fuse version` output shape (`TestVersionSubcommand` in `cmd/fuse`); install script is
  exercised by a `scripts/install_test.sh`-style shell test run under `bash -n` + a local-file-server
  dry run in the `release-dry-run` job (points `FUSE_RELEASE_BASE_URL` at the snapshot `dist/`).
- **CI**: the `release-dry-run` job above, on every push/PR.
- **Live**: the first real tag, `v0.1.0`, cut by the human after merge; the build evidence for this
  change records the snapshot run, not a published release (publishing is the human's act).

## Out of scope

- Homebrew tap, winget/scoop, Linux distro packages (deb/rpm/AUR), Windows builds.
- cosign signing and SBOM generation (attestation covers provenance; signing is a follow-on).
- release-please / automated version bumps and CHANGELOG.md maintenance.
- docker-compose stack and Helm chart — #76 consumes the image this change publishes.
- Publishing `sdk/ts` to npm — a separate change; its versioning cadence is independent.
- The `rentals-mcp` demo binary — never released.

## Open questions

1. **Pre-release `latest` gating.** GoReleaser's `docker_manifests` cannot be conditionally skipped
   per-entry in every version; if the pinned major lacks it, the `latest` manifest is instead pushed
   only from a workflow step gated on `!contains(github.ref, '-')`. Resolve at plan time against the
   pinned GoReleaser version.
2. **Attestation subject for the image**: derive the digest from `dist/artifacts.json`
   (`type == "Docker Manifest"`) with `jq`. Confirm the field name against the pinned version.
3. **Go version in the release job**: `go-version-file: go.mod` yields `1.26.5` — confirm
   `setup-go` resolves a patch-pinned toolchain without `check-latest`.
