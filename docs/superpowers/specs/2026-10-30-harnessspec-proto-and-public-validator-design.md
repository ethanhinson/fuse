# HarnessSpec proto and public validator - design

## Problem

A fuse harness is defined only by `internal/config`'s YAML loader (`~/.fuse/config.yml` +
`.fuse.local.yml`). Every client of the runtime other than the local CLI - the Go SDK, the
TS SDK, a remote caller of the networked binding - has no portable, versioned, IDL-defined
way to build, serialize, or validate a harness. `config.Config` also mixes the
client-settable harness surface with operator-only trusted settings that ADR-0006 keeps away
from lower-trust sources.

## Decisions

1. **Proto package `fuse.harness.v1`** at `proto/fuse/harness/v1/`, generated by the existing
   buf setup (`proto/buf.gen.yaml`, `make proto`), generated Go + TS committed (hermetic CI,
   drift-guarded like `fuse.loop.v1`).
   - `harness.proto`: `HarnessSpec` plus its messages, `HarnessService.ValidateHarness`
     (request: spec; response: `repeated Violation{field_path, message, rule_id}`). The
     service is defined, and a Go handler is provided, but fuse mounts it on no binding.
   - `options.proto`: `(fuse.harness.v1.ui)` field option `FieldUI{label, help, widget,
     secret_ref, tighten_only}` and `(fuse.harness.v1.value_ui)` enum-value option
     `EnumValueUI{display_name, help}` - metadata for clients that render a spec as a form,
     read from the generated descriptors. No validation semantics.
2. **Client-settable surface only.** Included: models (default alias + alias entries), skills
   (as `SkillRef{name}` references), remote MCP servers (`http`, `sse`, `streamable-http`;
   credentials as `client_secret_ref` names), permissions + auto mode, orchestrator, agents,
   workflows, throughput, context (summarization + relevance), pipeline synthesis caps,
   `max_turns`, `max_tokens`, research (custom-endpoint headers as literal-or-`secret_ref`).
   Excluded, each documented in the proto header: `gateway` (url/key/request_timeout),
   `loop_server`, `tool_identity`, `observability`, `skill_paths` (host dirs), `projects`
   (host-path keys), `permissions.auto.write_roots` (host dirs), stdio MCP servers
   (`command`, `env`: a host process) and `auth.token_file` (host path), sandbox substrate
   (an entry-point flag). A test walks the descriptor and fails if any of those names appear.
3. **protovalidate** (`buf.build/bufbuild/protovalidate`, a buf dependency pinned in
   `buf.lock`) for per-field shape rules: ranges, required/enum membership, URI and name
   patterns, secret-ref name shape, unique MCP server names, a reserved `default` model alias, no literal value for credential-named headers, and no literal starting with the reserved `secret-ref:` prefix (CEL). Go uses
   `buf.build/go/protovalidate`; TS uses `@bufbuild/protovalidate` (generated TS imports its
   bundled `buf/validate` descriptors via `rewrite_imports`).
4. **Public Go packages**: generated stubs at `github.com/ethanhinson/fuse/harness/v1`
   (`harnessv1`, plus `harnessv1connect`); the library at `github.com/ethanhinson/fuse/harness`
   with `Validate(spec) []Violation`, `ValidateShape(spec) []Violation`, `Violation{FieldPath,
   Message, RuleID}`, and `Service` (a `HarnessServiceHandler`). Public because a client in
   another Go module must be able to import the validator.
5. **`internal/config` stays the semantic authority.**
   - `Config.Problems() []Problem{Path, Message, Err}` holds the existing rules (unchanged),
     reporting every failure with its YAML key path; `Validate()` returns `Problems()[0]` with
     its byte-identical legacy text.
   - `config.FromYAML(data, source)` exposes the loader's trusted merge over `Default()` for an
     in-memory document (an extraction of `mergeFile`'s body, no behavior change).
   - Model-alias reference checks move from `cmd/fuse` (package main) to
     `internal/configcheck` (`Registry`, `ModelRefProblems`, `Problems`); cmd/fuse delegates.
6. **Mapping** (`internal/harnessconfig`, internal because its signatures name
   `config.Config`): `ToConfig(spec, SecretResolver)` renders the spec as the YAML the loader
   understands and resolves it through `config.FromYAML`, so merge semantics are the loader's.
   `FromConfig(cfg)` emits only values that differ from `config.Default()` and returns
   `[]Omission{Path, Reason}` for everything it cannot carry (operator-only blocks, stdio
   servers, host paths, inline secret values, negative numerics). Secrets: `ToConfig` resolves
   `secret_ref` names through a resolver; the default `PlaceholderSecrets` renders
   `secret-ref:<name>`, which `FromConfig` turns back into a ref, so validation never reads a
   secret value and round trips are lossless. `SpecPath` translates a config key path into the
   spec field path (or "" for a key the spec cannot express).
7. **Validator** = protovalidate shape violations + `config.Problems()` + model-ref problems on
   the mapped config, semantic paths translated by `SpecPath`, deduplicated per field (shape
   wins), sorted by path then rule id. Rule ids: protovalidate's, the proto's CEL ids,
   `fuse.config`, `fuse.model_ref`, `fuse.mapping`, `fuse.internal`.
8. **TS**: `@fuse/sdk` exports the generated harness types as the `harness` namespace plus
   `validateHarnessShape(spec)`. A shared fixture file (`harness/testdata/shape_cases.json`)
   drives both the Go and TS shape tests, so paths and rule ids stay identical across languages.

## Testing

- `internal/config`: legacy Validate text pinned per rule; Problems collects all with paths;
  FromYAML equals a trusted load.
- `internal/configcheck`: registry overlay, model-ref problems and text.
- `internal/harnessconfig`: empty spec -> `Default()`; field mapping; secret resolution;
  spec -> config -> spec and config -> spec -> config round trips; operator-only omissions;
  descriptor contains no operator-only field; `SpecPath`.
- `harness`: shape rules, semantic rules with spec paths, dedup, determinism, the Connect
  handler over a real round trip, UI options (labels everywhere, exact secret_ref and
  tighten_only sets, enum display names), generated-stub drift guard.
- `sdk/ts`: shared shape fixtures, UI options readable via `getOption`.

## Deferred

- Runtime consumption of a spec (StartLoop with a spec or revision), skill-ref resolution.
- Model-ref checks for workflow worker models (the CLI does not check them either; adding it
  would change CLI startup behavior).
- A cross-field rule that identity/token-exchange MCP auth requires `audience`.
